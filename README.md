# Чек-лист магазина

Ежедневный контроль открытия, обслуживания и закрытия магазина для двух сотрудников и владельца. Статический сайт с адаптивным интерфейсом и PWA; данные и проверка доступа находятся в Supabase Postgres.

## Возможности

- Личный чек-лист: 9 утренних, 2 дневных и 8 вечерних пунктов. Отказы с причиной учитываются отдельно от выполненных задач.
- Подтверждение утреннего/вечернего раздела после отметки предыдущих пунктов.
- Приход, уход и отмена свежих отметок в течение 60 секунд. Завершение смены сохраняет отчёт.
- Регистрация визитов покупателей с защитой от повторной отправки одного события.
- Панель владельца: дата, личные отчёты, причины отказов, смены, журнал визитов и общий результат по магазину.
- Московские дата, время и дедлайны проверяются сервером. Роль и сотрудник определяются серверной сессией.
- Без связи доступна только ранее загруженная копия. Новые отметки требуют подтверждения сервера.

Общий результат магазина означает, что задачу выполнил хотя бы один сотрудник. Личные отчёты показывают только действия выбранного сотрудника. Журнал визитов — количество нажатий, а не автоматический подсчёт людей.

## Запуск и проверка

Нужен Node.js 24 или новее.

```sh
npm ci --ignore-scripts
npm run dev
```

Откройте `http://127.0.0.1:4173`. Для рабочего входа сначала настройте [Supabase](docs/setup-supabase.md). В приложении нет демонстрационных PIN или обхода авторизации.

```sh
npm test
npx playwright install chromium
npm run test:e2e
```

Тесты работают на изолированной Postgres-базе PGlite с настоящими SQL-функциями. Браузерные тесты направляют RPC в эту базу, не меняют рабочие данные и не отправляют Telegram-сообщений.

## Устройство

`index.html` — вход; `employee.html` — сотрудник; `admin.html` — владелец. `js/api.js` вызывает ограниченные RPC; `js/auth.js` хранит срок действия сессии. SQL-схема и серверные проверки находятся в `supabase/`. Сборка для публикации не требуется.

В `js/config.js` разрешены URL Supabase, публичный API-ключ, названия профилей и задач. Секреты, PIN и токен Telegram в клиентский код добавлять нельзя. Публичный ключ идентифицирует приложение, но не даёт доступа к таблицам.
