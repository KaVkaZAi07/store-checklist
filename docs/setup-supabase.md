# Настройка Supabase

Новая версия использует серверную проверку PIN и сессий. Подробные SQL-команды и порядок установки находятся в [supabase/README.md](../supabase/README.md).

1. Убедитесь, что проект Supabase активен. Приостановленный проект не принимает отметки.
   Старые отметки могли остаться только на телефонах. Новая страница входа обнаруживает их и предлагает «Скачать прежние отметки». Архив сохраняется локально, исходные записи не удаляются. Не очищайте данные приложения до выгрузки. Автоматического импорта в подтверждённую серверную историю нет: происхождение и время таких отметок нужно сверить отдельно.
2. Проверьте SQL в `supabase/migration.sql` и примените его через SQL Editor. Скрипт создаёт таблицы чеклиста, серверные функции и ограничения доступа; существующие записи не нужно удалять.
3. Выдайте каждому профилю новый PIN через серверную процедуру из инструкции. Старые PIN из публичной версии использовать нельзя.
4. Проверьте `SUPABASE_URL` и публичный `SUPABASE_ANON_KEY` в `js/config.js`. Не подставляйте секретный или service-role ключ.
5. Проверьте вход каждого профиля, сохранение и просмотр владельцем. Затем публикуйте новую версию сайта.

PIN хранится в виде хеша, токен сессии — в виде хеша на сервере. Доступ ограничен сроком сессии. Ошибочные попытки входа ограничиваются сервером. Сотрудник работает только со своими записями; владелец читает отчёты всех сотрудников.

Время выполнения, московская дата, опоздание, срок отмены, порядок прихода/ухода и подтверждение раздела проверяются сервером. Изменение localStorage, имени сотрудника или часов устройства не даёт права изменять чужой отчёт.

Локальный кэш — только для просмотра ранее загруженных данных. Сайт не заявляет, что офлайн-отметка отправлена владельцу. При выходе кэш удаляется. Если сервер принял запрос, но ответ потерялся, обновите отчёт перед повторной отметкой.

База может также использоваться другим сайтом магазина. Изменения должны касаться только объектов чеклиста; не отключайте RLS и не выдавайте общие права на весь public.
